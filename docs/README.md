## How the pieces fit

`requirements.toml` is the one place requirements are written. `tools/trace.py render` turns it into the SRS and the
matrix, adding the evidence it finds in the code (`// VERIFIES: REQ-..` above each unit test) and in the
verification log (`Verifies:` lines). Nothing about the present state of the code is typed into those two documents
by hand, so they cannot drift quietly; `tools/trace.py check` fails when they or the bindings are out of date.

Document kinds (the `status:` line in each file's header): `living` is generated by a script and must be
regenerated, not edited; `design` is hand-written explanation of structure and intent; `ledger` is append-only
history. `tools/check_docs.py` validates the headers.

## Working on the docs

```sh
tools/gate.sh                  # unit tests, traceability check, header check (run before every commit)
python3 tools/trace.py render  # after changing requirements.toml, a VERIFIES comment or the verification log
python3 tools/trace.py self-test   # proves the checker still catches each kind of violation
```

Changing a requirement: a ratified statement is never edited. Retire it (`status = "retired"`, `retired_because`),
add a new ID with `supersedes`, and move or remove the tests that cited the old ID in the same change; the checker
fails while a retired requirement is still cited.
